# Isolated Godot client checks

The normal client accepts `--server-port=10310` in its user arguments, alongside the existing `--server=127.0.0.1`. Omitting the port retains 10300. Malformed and out-of-range ports disable connection before creating a client. C# `Open(host)` remains compatible; `OpenAt(host, port)` selects a development endpoint using the same protocol.

`--server-profile=lab` selects the exported DOLSharp LAB creation layout. The default `offline` retains the existing byte layout. Unknown names disable connection. `DaocClient.SetProtocolProfile()` accepts only these names, before a connection opens. The LAB still announces 1.127; this is a server-layout distinction, not a different advertised client version. Its `CreationCharacterData1124` parser reads three empty IntPascal strings (12 bytes versus Offline's 15 skipped bytes), and its final constitution byte follows 40 equipment bytes, a region byte and three padding bytes. Both use variable-length names; the old fixed-name parser is not used for 1.127.

LAB login first asks the permitted realm with request0. If the server returns no restriction, the normal realm screen chooses a realm before requesting its list. Unlike OfflineDAoC, prefetching Albion first can assign the LAB account's in-memory realm to Albion and make subsequent Hibernia requests return the wrong list. Existing realm restrictions and the selected realm are respected; logout refreshes only the selected LAB realm. Offline retains the three-realm prefetch. The gameplay test explicitly selects Hibernia, as the normal pregame screen does.

Build `source/new-client/godot/MMOEngine.csproj` with .NET 10 and the matching Godot 4.7.2 Mono SDK packages. Keep the SDK, NuGet cache, converted art and build outputs outside Git. Do not deploy over a running playable installation. Obtain authorization before starting even a copied server, as required by AGENTS.md.

The following development scripts run with the matching Godot Mono engine, `--path PROJECT --script res://enhanced/SCRIPT.gd -- ...`:

- `endpoint_check.gd`: parser checks with no network connection; use `--expect-port=PORT`, `--expect-active=true|false`, `--expect-client=true|false` and the endpoint arguments being tested. Invalid cases also use `--expect-error=true`.
- `compatibility_probe.gd`: protocol login, character list/creation, world entry, NPC/trainer interaction and a small movement. Requires a deliberately disposable account on a server copy.
- `gameplay_check.gd`: the normal Server autoload, zone scene, player and NPC rendering, fixed-light A/B captures and graceful logout. Requires an existing disposable Hibernian character in zone207 and matching converted art.

Both integration scripts read `--probe-config=ABSOLUTE_PRIVATE_JSON`. They reject endpoints other than loopback and reject the normal 10300 port. Do not use real account credentials or put the JSON in Git. The baseline configuration has `host`, integer `port`, `account`, `password`, `report` (protocol output file), and `output` (gameplay output directory). See the scripts for optional creation/interaction fields; a new server fork may require different creation rules. Passwords belong only in the private file, never in a process argument or report.

Set `profile` to `lab` in the private configuration for LAB tests; omitting it keeps `offline`. Use `expect_interaction_reply=true` to fail a requested NPC interaction if neither a message nor a trainer reply is received. Creation, world entry and rendered gameplay are separate checks. A successful creation does not verify character deletion, every customization operation, combat or the rest of the protocol.

Make a consistent SQLite backup with the source opened read-only before making an isolated copy. Bind the copied server to loopback on unused TCP/region ports; change only its own region endpoints and test data. Keep a hash manifest and the untouched snapshot separately from the disposable played copy. Disable copied autonomous population only for the controlled graphics baseline, without changing the original server's population or rules.

The local 20 October Offline baseline passed login, world entry, 142 protocol NPCs, a Caoimhe trainer reply and persisted movement. A rendered normal Ardee scene also passed. A subsequent independent LAB snapshot/export enabled the separate LAB profile: creation/world entry passed, then 82 protocol NPCs and a Caoimhe message were received in Ardee. Caoimhe declined to train the already-class47 test character; this verifies a reply, not a training session. The normal LAB scene also loaded zone207 and captured A/B. These checks do not cover combat, all customization/deletion operations, navigation or every packet. No database migration or deployment to the original clients/servers is performed.

## Local session entry point

`enhanced/lab_session.gd` is a developer entry point for the separate local launcher. It reads `--session-config=PRIVATE_JSON`, validates loopback10310/profileLAB, logs in, selects the named Hibernia character and enters zone207. Besides the private account/password/character fields, the configuration names a private `state_file` and `quit_file`. No credential appears in process arguments or status reports.

Creating the quit marker requests the normal server logout. This entry point handles the acknowledgement itself instead of returning to the pregame screen: it closes the managed socket reader, awaits `prepare_shutdown()` on the NPC and region loaders while the main/render loops remain alive, cancels new vegetation work and frees the scene before exiting. The loader hooks disable new work and join only after `WorkerThreadPool.is_task_completed()`; their normal `_exit_tree` paths remain as fallbacks. This avoids blocking the main loop while a worker may still need it. The supervisor then waits for its own copied server to finish saving/stopping and restores its own vegetation activation.

The session has no fifteen-minute play limit. Optional `self_test=true` caps the graphical lifecycle test at60 FPS; the normal interactive session uses the usual settings. The local launcher tests the same graphical engine path that its desktop shortcut uses. `enhanced/shutdown_check.gd` checks both loader hooks with workers deliberately waiting for a main-loop timer, without a server or DB. The final local end-to-end launcher check reached zone207 and exited client/server with code0, no forced termination, restoring activation; client shutdown took about6.4 seconds.
