# NPC ghost appearance: audit and private state candidate

The original production NPC-create packet carries ghost in flag 0x01. Godot applies a front-surface depth pass plus translucent original textures and a subtle cool-white rim. Monster opacity is 0.5; Catacombs race-figure opacity is 0.9, retaining skin/dye color and hair coverage. Original equipment is ghosted too. This is distinct from local-player stealth and must not reuse its gray/0.45 presentation.

The installed adapter retains realm/flying/name/targeting but drops the ghost rendering contract. The candidate adapter now publishes a separate `npc_visual` object from NPC-create only. NPC movement flags encode zone information and cannot replace create flags. Original NPC TORCH is separately normalized to database bit0x40; the original NPC view does not create a personal-light source from it, so the audit does not authorize adding NPC or building illumination.

`verify_npc_visual_flags.py` extracts the original Godot normalization block unchanged and compares all 256 first-byte combinations against representative second-byte states. The 1,815 candidate checks also cover malformed bytes, unrelated movement/player packets, reused identities, missing create data and copied-state isolation. Eight adapter checks exercise actual create/move/model/equipment/remove/region handling. Candidate metadata is not installed, and native consumption remains pending.

Private materials preserve source uniforms, textures and the original color/normal/specular/roughness graph. The render harness checks nonblank figures against a separate background and exact restoration; it hashes protected assets and the installed binary/catalogue. Initial diagnostic lighting and a moved backdrop produced misleading dark cuts, so neither fixture was accepted. The corrected fixture uses one common point light and recreates the backdrop for each viewpoint. Both models now pass front, back and two side comparisons: eight ordinary/ghost/restored sets, with zero restoration error. Filtered captures remove the inner eye/cloth/boot faces visible in the unfiltered diagnostic. This is static sample acceptance, not gameplay or full NPC model coverage.

The candidate actor-local controller now passes 44 native lifecycle checks, including MID uniforms, shared-asset isolation, equipment insertion/hiding, unknown/off state, replacement outfits, actor changes/removal and source draw-distance/bounds inheritance. Another 486 native movement/pose/combat/torch regressions pass. Its native render fixture captures 16 frames across two original idle poses per model, with nonzero pose changes and zero restoration error. The ordinary/ghost/reference materials and installed binary remain unchanged.

An isolated real-server run passes 28 checks using two ordinary players and three disposable NPC records (normal/ghost Zombie and ghost Celt). Both peers receive the original create-bit metadata. Private data and libraries are restored after normal client/server shutdown; the played installation is unchanged. This validates transport and the controller separately; normal NPC presentation integration and catalogue/material coverage are still pending, and nothing in this package is installed.

Offscreen commandlets use `-forceDisableDebugViewModes` (UE 5.8 `DebugViewModeHelpers.cpp`) to avoid compiling unused editor diagnostic permutations.

A read-only local population survey found ghost flags in existing world data, including models without exported native bodies and a Wisp whose effect is the body. Do not treat those as generic opaque figures or declare ghost appearance complete from flag tests. Private source exports use an original Zombie and Celt race figure as representative comparisons; world population imports remain separate.
