# Original consumables and current charge descriptions

Original healing potions work through the existing quickbar and DOL UseSlot packet. Real ordinary-player tests verify sitting, level and empty-charge refusals, healing, the shared reuse timer, consumption, last-charge removal and saved remaining charges. No potion requirements, spell data, cooldowns or consumption rules changed.

The tests reproduced a display defect: after using a two-charge potion, the server and a fresh inspection correctly reported one charge while the hover description retained two. DOL can update charges without sending an inventory packet. The bridge now discards that item's cached descriptions when requesting its original use and requests fresh original detail text. It never predicts consumption or treats the use request as success. A distinct queued detail key keeps an earlier in-flight answer from restoring old charges. Only a reply for the same current entry updates hover/inspection caches; superseded response keys are discarded, and missing replies leave statistics unavailable.

Evidence: 12 focused state checks (including older replies, replacement identity, timeout and cache cleanup); 226 compatibility checks across inventory, equipment refusals, handover, poison, original UI, hover and vault; 11 real checks for the remaining-charge case and 11 for last-charge removal; 11 additional real checks against the installed backend; 174 synthetic receipt-chain checks. The native plugin is unchanged from the verified hover delivery.

Installation replaces only classic_ui_state.gd with an exact predecessor hash and backup. It changes no server library, item template, map or played database. Test items exist only inside the marked disposable database, which is restored with its configuration and copied libraries after normal shutdown.

Owner review if a suitable potion is available: place it on a quickbar, read its charge count, use it while standing with missing health and hover it again. The remaining count should be current. A repeat inside its reuse period must retain the charge; the original refusal appears. A last charge removes the item and its old tooltip. Trying while seated or below the item's required level must preserve it. No potions or money were granted to played characters for these tests. Other item-specific scripts and every consumable family are not claimed as fully verified.
