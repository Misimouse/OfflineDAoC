# Existing original group lifecycle

This verification package checks the already integrated original group system. It does not replace runtime code or create an alternative group window.

References: original Godot panel_sheets group rows/buttons, bridge party_state and interaction state, and original DOL invite/disband commands. Nine real protocol checks use two ordinary accounts in a marked disposable database: decline without group creation, accept on both clients, actual member vitals, selecting the original server object, nonleader refusal, leader removal, stale roster refusal and voluntary leave. The private database, configuration and server libraries are restored after normal shutdown. The played database and normal server remain unchanged.

43 isolated state checks cover identity reuse, unknown vitals, original icons, stale membership, pending commands and joining-member update packets arriving before the expanded roster. 79 checks in the installed native client include group row targeting, confirmation/cancellation, exact roster token, mini group visibility and retained position. The native test uses existing widgets and commands; visual owner review is separate.

This is not acceptance of the eight-player maximum under load, raid/battlegroup UI, every group buff or cross-region behavior. Owner review can use the existing Group tab and mini group with a companion: select a row, invite, cancel/confirm removal and leave. No new launcher or setting is needed.
