# Player-trade gateway candidate

The production candidate routes four explicit trade actions through the normal session/id-gated visual transport. Beginning a trade validates the current inventory revision, carried item token, actual remote player name/model/session and nearby position, then calls original MoveItem to OID+1000. Opening remains pending until the original server window or inventory refresh; a refusal clears any invisible server-side trade allocation. A closed vault is not reset on every offer packet, avoiding unrelated inventory revision churn.

Data, libraries and navigation are restored; both ordinary clients/server exit normally.
